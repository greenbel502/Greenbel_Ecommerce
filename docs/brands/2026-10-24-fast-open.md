# Marcas: apertura local y reapertura del editor · 24/10/2026

## Fallo informado y diagnóstico de código

El usuario informó que Editar tardaba demasiado o no abría. La captura muestra una fila seleccionada y URL con marca, sin diálogo visible.

- Antes, Editar era un Link que cambiaba la consulta de página y esperaba autorización, cuatro listados del catálogo y comprobación de Storage para volver a renderizar el editor. Esas esperas no son necesarias para abrir una fila cuyos datos ya están cargados.
- El diálogo se sincronizaba solo con el booleano `editing`. El cierre nativo era inmediato y la retirada de `brand` dependía de otra navegación: cerrar y volver a seleccionar sin que ese booleano pasara por false podía dejar el diálogo cerrado. Es una condición identificada por inspección; no se afirma haber reproducido la secuencia en navegador.

## Cambio implementado

- Nueva marca y Editar son botones de UI. Seleccionan en estado local la fila ya autorizada; no invocan una navegación completa ni una petición del catálogo para abrir/cerrar una fila cargada.
- Apertura modal en `useLayoutEffect`, dependiente de la selección concreta, con instancia de diálogo vinculada al ID. Se sincronizan cierre/reapertura y cambio de marca, no solo un booleano.
- URL actualizada con History API integrada por la versión instalada de Next (comprobado en `node_modules/next/dist/client/components/app-router.js`). Conserva enlace directo, filtros y paginación; cambios de historial sincronizan el panel. Se ignoran snapshots atrasados de navegación al abrir/cerrar rápidamente.
- Registro seleccionado y logos confirmados se mantienen localmente. Refresco del servidor después de un guardado confirmado, o al recuperar una selección desconocida fuera de los datos disponibles; no al abrir una marca de la tabla.
- Filtros/paginadores de Marcas no conservan el parámetro transitorio de un editor cerrado. Se modifica solo la presentación de esos parámetros; consultas, reglas y permisos se conservan.
- Todas las lecturas iniciales y escrituras siguen protegidas en el servidor. No se concede acceso ni se verifica un rol únicamente en el navegador. No cambian la API del logo, su validación, el modelo o la secuencia de guardado.

Archivos de UI: `brands-admin.tsx`, callback de resultado confirmado en `brand-editor.tsx`, y exclusión del parámetro transitorio al construir controles de lista en `page.tsx`.

## Reanudación necesaria

Conectar Chrome y recargar una vez el panel. Probar Editar → X → Editar misma marca → X → Editar otra → Escape → Nueva marca, sin esperar navegación entre pasos. Inspeccionar que abrir/cerrar filas conocidas no genere GET/RSC del catálogo. Probar Atrás/Adelante, filtros tras cerrar, URL directa y móvil. Si aparece un fallo, corregir y repetir ese caso. Mantener como NO EJECUTADO hasta realizar esas interacciones.
